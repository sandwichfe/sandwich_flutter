总览表结构与关联

库内以 TEXT / INTEGER / REAL 三种亲和类型为主： 时间统一存为定宽 ISO 字符串（2006-01-02T15:04:05.0000000Z，UTC）， 布尔用 INTEGER 0/1，复杂结构（演员、媒体流、图片标签）以 JSON 文本存放。

users ─┬─ tokens tokens.user_id 指向登录用户，1:N。
libraries ─── items items.library_id 归属媒体库；items.parent_id 自关联形成 剧集 → 季 → 集 层级。
users + items ─── user_data 联合主键 (user_id, item_id)，存收藏、已看、续播位置、观看历史。
items ─┬─ item_people ─── persons 演员以 persons 为主表，item_people 是唯一的多对多关联。
items ─── item_groups 一行的条目属于某个分片组，item_id 即主键，单归属。
image_locks ─── 三类实体 entity_id 多态指向 items / persons / libraries，锁定后扫描不覆盖图片。
数据库版本：PRAGMA user_version = 9。全新库按 schema.sql 一次建到最新； 老库在 store.go 的 schemaMigrations 里逐级升级，不要求删库重扫。

登录账号。Emby 客户端的 AuthenticateByName 在本表校验密码并换取令牌。

user_data用户数据

每个用户对每个条目的个人状态：收藏、已看、续播进度、观看历史。 这是「观看历史」「收藏」和播放进度记忆的唯一数据来源。

主键 (user_id, item_id)
写入方 store/userdata.go · 收藏 / 已看 / 播报进度
读取方 列表查询的 LEFT JOIN、详情页 UserData
字段类型约束 / 默认说明
user_id PK FKTEXTNOT NULL用户，指向 users.id，与 item_id 组成联合主键。
item_id PK FKTEXTNOT NULL条目，指向 items.id。
is_favoriteINTEGERNOT NULL DEFAULT 01 = 已收藏。对应 Filters=IsFavorite。
playedINTEGERNOT NULL DEFAULT 01 = 已看完。播放停止上报时位置 ≥ 90% 自动置 1，也可手动标记。
playback_position_ticksINTEGERNOT NULL DEFAULT 0续播位置（100ns）。played = 1 时清零；> 0 时卡片显示进度条并支持续播。
play_countINTEGERNOT NULL DEFAULT 0播放次数。手动标记已看时 +1。
last_played_dateTEXTNOT NULL DEFAULT ''最近播放时间。观看历史的判定与排序依据：非空即算播放过。
索引：idx_user_data_played(user_id, last_played_date) 服务按最近播放排序； idx_user_data_resume(user_id, played, last_played_date) 名字沿用旧版「继续观看」， 当前服务于观看历史的时间过滤与排序。

多对多关联表。同一演员在同一条内容里可能既是导演又是编剧， 所以唯一键必须包含 type 和 role。

主键 (item_id, person_id, type, role)
索引 idx_item_people_person(person_id)
写入方 扫描入库 / 演员关联维护
字段类型约束 / 默认说明
item_id PK FKTEXTNOT NULL条目，指向 items.id。
person_id PK FKTEXTNOT NULL人物，指向 persons.person_id。
type PKTEXTNOT NULL DEFAULT ''参与类型：Actor / Director / Writer 等。
role PKTEXTNOT NULL DEFAULT ''角色名（演员表里的饰演角色），导演/编剧通常为空。

item_groups分片影片归属

一部影片被切成 _1 / _2 多个文件时，用它把同组的条目串起来。 单归属设计（item_id 作主键）：一个物理文件只可能是某部作品的一段。 只有带明确序号后缀的文件才写行，普通影片一条都不写。

主键 item_id
索引 idx_item_groups_key(group_key)
写入方 扫描旁路 + 老库 BackfillItemGroups 回填
字段类型约束 / 默认说明
item_id PK FKTEXTPRIMARY KEY分片条目，指向 items.id。
group_keyTEXTNOT NULL组标识 = library_id | 相对目录 | 归一化标题，算法见 internal/partgroup。
part_indexINTEGERNOT NULL DEFAULT 0文件名里的原始序号（从 1 起）。存原始值而非组内位置，缺号时才看得出原始编号。
part_countINTEGERNOT NULL DEFAULT 0组内成员数，冗余字段，省掉详情页每次 COUNT(*)。

image_locks图片锁

被锁定的条目 / 演员 / 媒体库，扫描导入与自动重拼封面都不会覆盖其图片。 单独一张表而不是在 items 加列，因为锁要同时覆盖三类实体。

主键 entity_id（多态）
写入方 图片上传 / 手动换图流程
指向 items.id 或 persons.person_id 或 libraries.id
字段类型约束 / 默认说明
entity_id PKTEXTPRIMARY KEY被锁实体 ID，类型由调用方上下文决定（条目 / 人物 / 媒体库）。
created_atTEXTNOT NULL加锁时间。

业务规则跨表约定

  • 观看历史：user_data.last_played_date <> ''，按该字段倒序。已看完的条目也保留。
  • 续播进度：playback_position_ticks > 0 AND played = 0 时卡片显示进度条，起播时作为 StartPositionTicks。
  • 看完判定：只在 Sessions/Playing/Stopped 上报时判断，位置 ≥ 时长 90% 则 played = 1 并清零续播位置。
  • 收藏：user_data.is_favorite = 1，对应查询参数 Filters=IsFavorite。
  • 增量扫描：items.fingerprint（size:mtime）不变且 nfo_mtime 未变时跳过 ffprobe。
  • 演员展示：以 persons + item_people 为准，items.people 仅作入库快照。
  • 图片缓存失效：image_tags / backdrop_tags / screenshot_tags / persons.image_tag / users.primary_image_tag 变化即让旧 URL 失效。
  • 外键：schema 未声明 FOREIGN KEY，关联完整性由应用层与扫描流程保证。
